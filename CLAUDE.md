# Operating rules

This repo mines a dataset of computational complexity theory papers. Read
`SCOPE.md` before making any screening decision; follow
`prompts/mine-dataset.md` for the run itself.

## The one rule that matters

**Never write a paper, a title, an author, a venue, a year, a DOI, a number,
or a quotation from memory.** Every fact in this repo must come from a
response that a script or a fetch returned in this session.

You know this literature. That knowledge is for *deciding what to search for*
and *judging what you find* — never for filling in a field. This field makes
the failure especially easy: the canonical results have names, and a name is
enough to reconstruct a citation that looks right and is wrong. A plausible
citation is worse than a missing one, because it is invisible.

If a lookup fails, set `status: unavailable` and move on.

`scripts/verify_citations.py` enforces this: it re-resolves DOIs and arXiv ids
against live APIs and compares the returned title to the stored one. Run it
before declaring anything finished.

## No model is in this pipeline

Every source is free, keyless, and unmetered: arXiv, Crossref, OpenCitations.
No script here calls a language model, and none should. The only judgement an
agent makes is the core-tier screening decision in Phase 2, and that is made
by reading a fetched abstract against `SCOPE.md`.

Never add a keyed or metered source. It fails partway through an unattended
run, which is worse than not having it.

## Where state lives

| Path | What it is |
|---|---|
| `SCOPE.md` | The scope contract. Screening decisions are made against this |
| `papers/library.jsonl` | Every paper seen. One JSON record per line, deduped |
| `dataset/` | The deliverable. Generated by `scripts/dataset.py` — never hand-edit |
| `STATUS.md` | Live run state. The handoff if the session dies |
| `logs/events.jsonl` | Structured record of every query and its yield |
| `.cache/` | Raw API responses. Gitignored; makes re-runs free |

## Pipeline

```bash
python3 scripts/search_arxiv.py --queries-file config/queries.txt --max 200
python3 scripts/enrich.py                       # DOIs, venues, missing abstracts
python3 scripts/screen.py next --limit 25       # candidates -> stdout as JSON
python3 scripts/screen.py apply decisions.json  # decisions -> library, in bulk
python3 scripts/snowball.py --seed-status included
python3 scripts/dataset.py --edges              # the deliverable
python3 scripts/verify_citations.py --all       # gate: citations; non-zero on error
```

Every script is idempotent and resumable — safe to re-run after any crash.
Nothing needs installing; it is all stdlib.

`enrich.py` is not optional. arXiv supplies almost no DOIs, and **both citation
sources are keyed on DOI**, so its Crossref title match is what makes
snowballing possible. Run it after every harvest and every snowball round.

## Working rules

- **Screen in bulk.** `next` emits a batch, `apply` writes the verdicts back.
  - Never one subprocess per paper.
- **Screen from the abstract, not the title.** The abstract is in the batch JSON.
  - No abstract? Run `enrich.py`. Still none: mark `unavailable` rather than guess.
- **`signals` is a prior, not a verdict.** It is a keyword match; good papers trip it.
- **Checkpoint constantly.** Every batch: update `STATUS.md`, then `git commit`.
  - A lost batch costs ten minutes. A lost session costs the run.
- **Record why.** Every include and exclude carries a `reason`.
  - A decision without one cannot be reviewed later.
- **Failures are data.** A paper you could not fetch is `unavailable`, with the reason.
  - Never drop it silently, never fill the gap from memory.
- **Report reach, not just yield.** Every script prints what it could not
  reach — seeds without a DOI, references deposited as unstructured text,
  papers OpenCitations has no data for. Those numbers separate "the literature
  is thin here" from "our sources are thin here". Only the first is a finding.

## Style

`.claude/skills/my-concise/SKILL.md` governs `STATUS.md` and anything said to
the user: bullets, one claim each, near 100 characters, no hedges. Run
`python3 scripts/style_check.py STATUS.md` to check the mechanical part.

This repo produces no prose deliverable, so the style surface is small. Keep it
that way — a claim written down here is a claim someone has to check.
