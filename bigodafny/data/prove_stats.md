### Fresh rows versus redrawn rows

A row that fails stays in the pool, so each plain draw carries more
rows an earlier campaign already failed. That share is not constant,
and the pooled headline above mixes the two populations.

|---|---|---|---|---|---|
| `prove-sample` | 50 | 0 | 0% | 42/50 | — |
| `prove-sample-2` | 48 | 2 | 4% | 37/48 | 0/2 |
| `prove-sample-3` | 45 | 5 | 10% | 37/45 | 2/5 |
| `prove-sample-4` | 44 | 6 | 12% | 35/44 | 3/6 |
| `prove-sample-5` | 38 | 12 | 24% | 30/38 | 7/12 |
| `prove-sample-6` | 36 | 14 | 28% | 24/36 | 6/14 |

Only a fresh-row rate answers the campaign's own question. From
campaign 7 the sampler is run with `--exclude-drawn`, which draws only
never-touched rows: earlier campaigns removed a random part of the pool
(what they proved) and left a non-random part (what they failed), so
the never-drawn remainder is still an unbiased sample of the original
population.

### Deduplicated: one record per distinct row

The headline counts draw records. A row several campaigns drew is
in it several times, and those are disproportionately the hard
rows, since a repeat draw selects for failure. `dedupe.py` keeps
one record per row — the most positive outcome — and writes the
rest out as `superseded`.

- 32 rows were drawn more than once.
- 16 were closed by a later campaign after an earlier one missed them.
- Excluded because they have not finished: `prove-sample-7`. A running campaign has rows with no record yet, and counting those as failures would move every number here.

**These two rates answer different questions.** The raw rate asks
what share of the rows a campaign drew that campaign proved inside
its budget. The deduplicated rate asks what share of the distinct
rows anyone has drawn now carries a proof. The second is higher by
construction and says nothing about what one bounded agent manages
in one pass; use it for the corpus, never for comparing campaigns.

## Why the failures failed

| obstacle | rows | share |
|---|---|---|
| `z3-nonlinear` | 32 | 42% |
| `value-to-size` | 19 | 25% |
| `invariant-gap` | 12 | 16% |
| `decreases-star` | 8 | 10% |
| `budget` | 2 | 3% |
| `prelude-gap` | 2 | 3% |
| `recursion-depth` | 1 | 1% |
| `label-mismatch` | 1 | 1% |

| obstacle | what it means |
|---|---|
| `value-to-size` | the cost depends on how LARGE an input is; the label counts how MANY. Needs its own arithmetic lemma per row |
| `z3-nonlinear` | the solver would not close a verification condition mixing several nonlinear scaffolds |
| `invariant-gap` | an invariant needed reshaping or one more bridging assert |
| `decreases-star` | the row carries `decreases *`, so there is no termination proof to hang a step bound on |
| `prelude-gap` | a lemma the prelude does not have. Fixable ONCE for every row that hits it |
| `recursion-depth` | bounding a recursion depth needs a number-theoretic argument |
| `structural-unbounded` | no bound in the row's size exists |
| `budget` | the mechanism was in hand when the clock ran out |

Every bound here is an **upper** bound. It can confirm a label or fail
to; refuting one takes a lower bound, which no campaign produces.

These are the relations each campaign RECORDED. Where a finding was
later acted on, the row's current relation differs and the resolution
is noted below rather than overwritten, so the finding is not erased:

- **`1243_0`** — Acted on 2026-09-21: the Dafny was re-translated to sort, as the Python does, and re-proved at the tight two-term bound 2*|s1|*(CeilLog2(|s1|)+1) + 2*|s2|*(CeilLog2(|s2|)+1) + 3*|s1| + |s2| + 5. The row's CURRENT relation is confirms; this record keeps what the campaign found.

| relation | meaning |
|---|---|
| `confirms` | the bound is within the label's class |
| `looser-slack` | a loose scaffold was used; the tight bound was not attempted |
| `looser-structural` | the proof exposes a real cost the label omits |
| `tighter-costmodel` | the bound is below the label because the charge table costs something CPython does not |
| `tighter-translation` | the bound is below the label because the Dafny runs a cheaper algorithm than the Python |
| `contradicts` | a literal in the source forces more work than the label allows |

## What this does not measure

- **Only `solutions/`.** The 127 unscreened and 157 disputed rows have
  never been drawn. Nothing here generalises to them.
- **A bounded agent, not the problem.** `unresolved` means 3 attempts
  and 5 minutes were not enough, not that the row cannot be proved.
  `2423_48` failed twice and then closed once the prelude gained the
  lemma it needed.
- **Upper bounds only.** No campaign can show a label is too small.
