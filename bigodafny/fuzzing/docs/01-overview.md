# 1. Overview

## The tools

| Tool | Question it answers |
|---|---|
| `steptrace.py` | What is `steps` on this input, and at each program point? Does the proved bound hold? |
| `stepfuzz.py` | For each input size, which input makes `steps` largest? Which growth class fits? |
| `DafnySteps deghost` | What program does the plugin compile? |
| `DafnySteps annotate` | Given a plain row, where does a step counter go, and what does each statement cost? |

## Layout

```
fuzzing/
  steptrace.py          run one row's counter on inputs; Runner, the harness
  stepfuzz.py           MAP-Elites search for costly inputs; uses steptrace.Runner
  TODO-fuzzing.md       requirements, open items
  docs/                 these files
  demo/                 sample deghost and annotate output
  DafnySteps/           C#; one DLL that is both a CLI and a Dafny plugin
    DafnySteps.csproj   references the installed Dafny's DLLs
    Ast.cs              load, walk, print Dafny programs; small helpers
    Deghost.cs          the deghost pass: ghost counter -> compiled
    Plugin.cs           runs Deghost inside `dafny`, before resolution
    Annotate.cs         the annotate pass: plain row -> row with ghost counter
    CostModel.cs        COMPLEXITY.md's charges, per expression
    Program.cs          CLI entry: `deghost`, `annotate`
```

## Data flow

```
solutions-proved/P/SID.dfy  (ghost steps, proved bound)
   │  dafny translate py --no-verify --plugin "DafnySteps.dll,trace contracts points=…"
   │        └─ Plugin.cs → Deghost.cs runs on the parse tree, before resolution
   ▼
.build/trace_SID_t/out-py/module_.py   Solve(..) returns (output, steps)
   │  harness.py (generated by steptrace.py): Input.from_str → Solve → JSON line
   ▼
steptrace.Runner.run(text) → {"status", "steps", "hits", "bound_ok"}
   │                               │
   ▼                               ▼
out/trace/SID.jsonl            stepfuzz.py → out/fuzz/SID.json
```

- `annotate` comes before this flow: it gives a plain row a ghost counter.
- Its output resolves but does not verify.
- `steptrace.py --dfy FILE` runs an annotated file; nothing calls it automatically.

## Quick start

```bash
cd bigodafny && source .venv/bin/activate
dotnet build -c Release fuzzing/DafnySteps        # after every .cs edit
cd fuzzing
python3 steptrace.py 1011_368                     # steps on each stored test
python3 steptrace.py 1011_368 --trace             # plus per-point hits and steps
python3 steptrace.py 1011_368 --input in.txt      # one input from a file
python3 steptrace.py 2286_319 --dfy demo/2286_319.annotate.dfy   # run another .dfy
python3 stepfuzz.py 1011_368 --iters 300          # worst input per size bucket
python3 stepfuzz.py 1011_368 --measure "i.n"      # size = an expression over Input `i`
D=DafnySteps/bin/Release/net10.0/DafnySteps
$D deghost ../solutions-proved/1011/1011_368.dfy out.dfy trace contracts points=p.json
$D annotate ../solutions-disputed/1011/1011_368.dfy out.dfy   # notes go to stderr
```

- `steptrace.py` builds the DLL only when it is missing.
- After a `.cs` edit, run `dotnet build` yourself, or the scripts use the old pass.
